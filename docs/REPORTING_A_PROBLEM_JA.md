# 問題を報告する

多重化がうまくいかないとき、tsMuxeR が作る 2 つのファイルがあれば、映画全体を送らなくても原因を探せます。

| ファイル | 内容 | サイズ | 送るとき |
|---|---|---|---|
| **レポート** | 実行の記録を書いたテキストファイルです。tsMuxeR に渡された内容、すべてのメッセージ、各トラックが読み取ったものと除外したもの、書き出したものが入っています | 小さい | すべての問題で |
| **サンプル** | ソースの一部をバイト単位でそのままコピーした .zip ファイルです | 最大 25 MB | レポートだけでは足りないとき、または依頼されたとき |

どちらもウィンドウまたはコマンドラインで作成できます。[「Bug report」フォーム](https://github.com/teaching-droid/tsMuxer/issues/new/choose)で新しい issue を作成し、添付してください。ファイルはフォームにドラッグできます。

**issue は公開されます。** レポートには映像も音声も含まれず、ファイル名も置き換えられます。サンプルには映画そのものの一部が含まれるため、共有してよい場合にだけ添付してください。

## ウィンドウで行う

### レポートを作成する

1. **全般** タブを開き、**問題報告用に、多重化ごとにレポートを書き出す** にチェックを入れます。
2. 問題が起きるように、ジョブをもう一度実行します。
3. ジョブが終わったら、進行状況ウィンドウで **レポートを保存...** をクリックします。
4. 表示された内容を読んでから保存します。

### サンプルを作成する

1. **入力** タブの一覧でファイルを選び、**サンプルを作成...** をクリックします。ジョブがエラーで終わったときは、進行状況ウィンドウからも作成できます。
2. **取得範囲** で **先頭**、**末尾**、**この時刻の前後 (問題のある箇所)** のいずれかを選び、時刻を指定します。
3. **サイズ** は表示された値のままにするか、小さい値を選びます。.zip は 25 MB 未満に収まります。
4. 前回のジョブのレポートがある場合は、**最後のジョブのレポートを追加** にチェックを入れます。**レポートを表示** で先に内容を確認できます。
5. **保存先** で .zip の保存場所を選び、**サンプルを作成** をクリックします。

## コマンドラインで行う

問題が起きるジョブに `--report` を追加します。

```
tsMuxeR --report=report.txt film.meta film.ts
```

次に、問題が起きる時刻の前後からサンプルを作成し、そのレポートも入れます。

```
tsMuxeR --make-sample --at=1:02:13 --add-report=report.txt film.mkv sample.zip
```

| オプション | 動作 |
|---|---|
| `--from-start` | ソースの先頭を取得します。これが既定です。 |
| `--from-end` | ソースの末尾を取得します。 |
| `--at=<時刻>` | 指定した時刻の前後を取得します。h:mm:ss または秒で指定します。 |
| `--size=<MB>` | サンプルのサイズを 1 から 24 MB で指定します。指定しない場合は 20 です。 |
| `--add-report=<ファイル>` | 問題が起きたジョブのレポートを .zip に入れます。 |

レポートの名前には、ジョブのファイル (ソース、メタファイル、出力) と同じ名前は使えません。サンプルも、そのソースや、サンプルに入れるレポートに上書きすることはできません。tsMuxeR はこれらの名前を拒否し、その旨を表示します。

## レポートの内容

* tsMuxeR のバージョンとシステム情報 (システムのバージョン、プロセッサ数、メモリ、実行時刻)
* コマンドラインとメタファイル
* 各ソースのサイズと先頭 32 バイト、およびその一覧
* 実行中のすべてのメッセージと、その時刻 (秒)。画面に表示されない行も含みます
* 各トラックが読み取ったもの、使用したもの、除外したもの
* 書き出したファイルとそのサイズ

**名前は公開されません。** すべてのパスからフォルダーが除かれます。ファイル、タイトル、トラック、チャプターの名前は `<source1>.mkv` のような仮の名前に置き換えられます。Names という項目には、長さや空白の有無など、名前に関する問題を探すのに必要なことだけが書かれます。`00800.mpls` のようなディスク内のファイル名はそのまま残ります。

依頼された場合にだけ、`--report-keep-names` で名前を、`--report-full-paths` でフォルダーも残してください。`--report-frames` を指定すると、書き出したストリームの各部分を 1 行ずつ記録した、はるかに大きい 2 つ目のファイルが追加されます。`--report-frames=0:10:00-0:12:00` のように時間の範囲を指定してください。

## サンプルの内容

* **ソースの一部**: バイト単位でそのままコピーするので、ソースと同じ問題が再現します
* **サンプル作成のレポート**: ジョブのレポートを追加した場合は、それも入ります

.zip の中のファイル名は `source1` に元の拡張子を付けたものになります。Matroska のサンプルではトラックとチャプターが残りますが、タイトルとトラック名、チャプター名は空になります。タグ、添付ファイル、インデックスは含まれません。

サンプルは読み取りを開始できる位置から始まるため、指定した時刻より少し前から始まることがあります。サンプルに収まるソースは全体が取得され、末尾より後の時刻を指定すると末尾が取得されます。

ソースによっては制限があります。

| ソース | 制限 |
|---|---|
| MP4、MOV | 先頭だけを取得できます。`--at` と `--from-end` は拒否されます。 |
| 単体の映像ストリーム | 時刻情報がないため、先頭か末尾を取得してください。 |
| ディスクイメージ内のファイル | `film.iso/BDMV/STREAM/00001.m2ts` のように、イメージの後にパスを続けて指定します。 |

ソースの種類ごとの詳細は、[USAGE](USAGE.md) の「Sample for a problem report」(英語) をご覧ください。

## そのほかに役立つ情報

* 期待していた結果と、実際に起きたこと
* 再生の問題の場合は、使用したプレーヤーや機器

レポートにはバージョン、メタファイル、ログ全体がすでに含まれているため、レポートがあればこれらを貼り付ける必要はありません。
